# Phase 3A 착수 준비 판정 · 기능 분리 · Blocker · Phase 3 구현 계획

> 2026-10-16 · 브랜치 `vnext-phase3a-prep` · 관련 문서: [SCREEN_VERIFICATION.md](SCREEN_VERIFICATION.md), [DATA_CONTRACT.md](DATA_CONTRACT.md)

## 판정: **조건부 가능**
| 근거 | 상태 |
|---|---|
| 현행 화면·엔진 안정성 | ✅ 6개 고객 화면 검증 PASS(API·정적), 끝값 954건 = 엔진 값, 겹침 0/144, 회귀 테스트 전체 통과 |
| 점수와 근거 수준 분리 / 가설 표시 | ✅ 근거 충분이 아닌 6개 영역은 ③·④에서 모두 '가설' 표시(41/41) |
| 데이터 계약 | ✅ v0.1 초안을 기계 판독 계약과 검증기로 구현했고, 합성 데이터 18개 테스트 통과(원본 보존·승인값만 공식·정의 미확정 시 판정 보류) |
| 외부 데이터만으로 할 수 있는 기능 | ✅ 즉시 착수 가능(아래 A군) |
| 사내 데이터에 의존하는 기능 | ⛔ 실제 사내 Excel의 헤더·정의·승인 체계를 아직 확인하지 못함(B1~B4, B6, B8) → B군은 보류 |

정리하면 다음과 같습니다.
- **A군(외부 데이터 기반 + 계약·저장 기반 구축)은 바로 착수할 수 있습니다.**
- **B군(사내 값이 들어가야 의미가 있는 기능)과 실제 사내 데이터 Import는 Blocker가 해소된 뒤 진행합니다.**
- A군만 진행해도 사내 값이 들어올 자리(빈 상태 화면 포함)는 모두 준비됩니다.

## 1. Phase 3A 기능 분리
### A군 — 현재 외부 데이터로 가능
| ID | 기능 | 사용 데이터 | 산출 | 공수(추정) |
|---|---|---|---|---|
| A1 | 대사 저장 구조 + 계약 v1 + Import v2 템플릿·검증(합성 데이터) | 계약 v0.1, 합성 데이터 | 새 시트 5종 preview/verify/approve(샌드박스) | 3~4일 |
| A2 | 고객별 대사 패널(빈 상태 포함): 외부 TS/RAW/FPR ↔ 사내 6개 필드, 상태 배지(원천/검증/승인) | 외부 엔진 + 빈 사내 레이어 | ① 화면 Reconciliation 영역 개편 | 2~3일 |
| A3 | 전략과제 후보 카드 WHY/GAP/OPTION/ACTION. 근거 충분 영역만 '우선 검토', 나머지는 '검토 가설' | strategy, area_evidence, signals | ③ 화면 | 3~4일 |
| A4 | 근거 표시 세분화: '기존 지출 관측' vs '신규 수요 신호'(F7-2), '성장 가정 주의' 플래그(F7-1, 가정 의존도 > 50%) | 현행 evidence 필드 | 표시만, 점수·등급 불변 | 1일 |
| A5 | 가중치 민감도: 현행 점수 산식 그대로 가중치 ±10pp일 때 순위 변동 | 현행 점수 입력 | 순위 안정성 표 | 1~2일 |
| A6 | ② 전사 부분합 궤적(커버리지 n/53 표기, 정의 상이·결측 제외 명시) | 외부 엔진 | ② 화면 | 1~2일 |

### B군 — 사내 데이터 검증 이후 가능
| ID | 기능 | 선행 조건 |
|---|---|---|
| B1 | 실제 매출 기반 C-SOW·Potential Capture Rate·Upside(공식) | APPROVED ACTUAL_REVENUE, B6·B7 |
| B2 | 승인 목표 기반 Target SOW·Gap-to-Target, 목표 > FPR 경고 | APPROVED_TARGET, B4 |
| B3 | 승인된 Sales Plan을 매출 계획 경로(실선)로 표시. TS/RAW/FPR 보간과는 별도 | APPROVED SALES_PLAN, B10 |
| B4 | 고객 × 사업영역 내부·외부 RAW 차이 히트맵(DIRECT 판정) | B2·B3·B5 정의 확정 |
| B5 | 사내 파이프라인·계약 근거로 근거 tier 재판정 | INTERNAL_PIPELINE/CONTRACT 승인 레이어, B8 |
| B6 | 고객 우선순위(매출 갭 반영), 사내 RAW 채택(ADOPTION) 의사결정 | B1·B4 + 경영 결정 |

## 2. 두 번째 프롬프트(사내 데이터 연동) 실행 전 해결할 Blocker
| # | Blocker | 왜 막히는가 | 해소 방법(사용자 측) | 차단 범위 |
|---|---|---|---|---|
| **B1** | 실제 사내 53-KA Excel의 시트 구성·헤더·행 단위·병합 셀·수식 미확인 | 헤더 매핑(`internal_header_map.json`) 작성 불가 | **값을 지운 양식**(헤더·샘플 1행을 가상 값으로) 제공 | Import 전체 |
| **B2** | Internal SAM 정의(TS 대응인지 RAW 상위인지, 무선·단말 포함 여부) | 비교 쌍과 판정 방식 결정 불가 → 현재 NOT_COMPARABLE | 정의서 1단락 + 산출 범위 | B4 |
| **B3** | RAW 역산 보정 방법(산식·입력·보정 주체·주기) | 사내 RAW가 PROXY에 머묾. 목표 연동 역산이면 순환 위험 | 산식 설명(예: 계획매출 ÷ 목표 SOW) | B4·B6 |
| **B4** | 2031 Target Case 이름·개수·산식, 승인 케이스 선택 방식, 승인권자 | 케이스 → 승인 목표 연결(C07) 불가 | 케이스 목록·승인 절차 | B2 |
| B5 | 사내 상품군 → 9개 카테고리/8개 사업영역 매핑 | 영역 단위 대사·근거 연결 불가(C08 격리) | 상품군 목록 → 매핑표 합의 | B4·A3 연계 |
| **B6** | 사내 고객 코드 ↔ KA01~53 매핑, 그룹·계열사 합산 범위 | 계정 미매핑 시 격리, 법인 범위 차이로 오판 | 사내 고객코드·사업자번호 대응표 | B1~B6 |
| B7 | 매출 기준(인식/수주), VAT, 단위 | CR 비교 오차 | 회계 기준 확인 | B1 |
| **B8** | 사내 데이터 취급 보안 승인(저장 위치·열람 권한·반출 금지 확인) | 실데이터 적재 불가 | 보안 담당 승인, 운영 PC/서버 지정 | 실데이터 전체 |
| B9 | RACI(업로더·검증자·승인자 지정) | 직무 분리(C04) 운영 불가 | 역할별 담당자 지정 | 승인 흐름 |
| B10 | Sales Plan·Stretch 연도 범위(연도별 2027~2030 존재 여부) | 매출 계획 경로 구성 불가 | 양식 확인(B1과 함께) | B3 |

**굵게 표시한 B1·B2·B3·B4·B6·B8은 두 번째 프롬프트를 실행하기 전에 반드시 해소해야 합니다.**
- 나머지(B5·B7·B9·B10)는 Import 파일럿 중에 함께 해소할 수 있습니다.
- A군 착수에는 Blocker가 필요 없습니다.

## 3. Phase 3 구현 계획(승인 후)
| 단계 | 범위 | 기간(추정) | 완료 기준(KPI) |
|---|---|---|---|
| **3A-1** 계약·저장 기반 | A1: 계약 v1(Blocker 해소분 반영), `excel_io` 새 시트 추가(기존 4개 시트 불변), verify 단계, 대사 보고서 | 1주 | 합성 데이터 테스트 + 기존 Import 테스트 전부 통과, 기존 53개 KPI 기준선 불변 |
| **3A-2** 화면 | A2·A4·A6: 대사 패널(빈 상태), 근거 세분 표시, 전사 부분합 궤적 | 1주 | E2E에 대사 패널·상태 배지 검증 추가, 정적 HTML 동일, 겹침 0 |
| **3A-3** 전략과제 | A3·A5: WHY/GAP/OPTION/ACTION 후보, 가중치 민감도 | 1주 | 근거 충분이 아닌 영역의 CONFIRMED 표시 0건(C11 + E2E), 점수 산식 불변 |
| **3B** 사내 데이터 파일럿 | Blocker 해소 후 3~5개 고객, 실제 양식 헤더 매핑 → preview → verify → approve(사내 PC 샌드박스) | 1~2주 | 원본 해시 보존 100%, 격리 사유 전수 설명, 공식 슬롯 = 승인값만 |
| **3C** 전체 확장 | 53개 고객, B1~B5 기능, ADOPTION 의사결정 자료 | 2주 | 고객 × 영역 대사 커버리지, REVIEW 건 사유 기재율 100% |

원칙:
- 매 단계 시작 전에 기존 정상 버전을 태그로 고정합니다(로컬).
- 매 단계 회귀 세트를 실행합니다: pytest(기준선 포함), vitest(끝값 954건), E2E(API·정적), 겹침, 화면 검증, 전략 근거 점검.
- 매 단계가 끝나면 사용자 승인 후 다음 단계로 넘어갑니다.

## 4. 승인 요청 사항
1. 판정(**조건부 가능**)과 A군 우선 착수(3A-1 → 3A-3) 승인 여부
2. 계약 v0.1의 핵심 규칙 확정
   - (a) 사내 SAM/RAW는 비교 전용
   - (b) 공식 슬롯은 APPROVED만
   - (c) 정의 미확정이면 판정 보류
   - (d) Target Case 자동 승격 금지
3. Blocker B1·B2·B3·B4·B6·B8 자료 제공 일정
4. 시각 변경(점선 추정 경로·채운 끝점 마커) 확정 여부
